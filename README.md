# Phan's Custom Tailor website

A static, three-language site (English at `/`, Vietnamese at `/vi/`, Simplified Chinese at `/zh/`). It's generated from `src/` by a Node script with no dependencies. The shop reads products from WooCommerce's Store API once that's connected; until then it reads sample data.

## Folder

```
build.mjs                  generates dist/ from src/
src/config.json            contacts, social links, site URL, shop and form settings
src/i18n/{en,vi,zh}.json   all page copy, one file per language (slugs shared)
src/data/                  prices, reviews, journal posts, sample products, image sizes
src/styles/site.css        the stylesheet (tokens at the top)
src/js/site.js             menus, shop filters, enquiry form, tracking
src/js/motion.js           GSAP scroll and hover motion, page transitions, three.js cloth effects
src/vendor/                GSAP 3.13 (gsap, ScrollTrigger, SplitText) and three.js r170, self-hosted
src/brand/logo.svg         the PHAN'S wordmark, traced from the original PNG
assets/img/                WebP photos (generated by scripts/prepare-images.py)
assets/brand-out/          favicons, logo PNGs
assets/share.jpg           1200x630 social share image
scripts/                   prepare-images.py, qa.py, shots.py, perf.py, copy-deck.py
_source/                   crawl of the old site, stock photos and their sources (not deployed)
dist/                      the built site (deploy this)
qa/                        QA screenshots
```

## Preview locally

```
node build.mjs
cd dist && python3 -m http.server 4321
```
Open http://localhost:4321.

## Edit content

- **Copy:** edit `src/i18n/en.json`, then the matching keys in `vi.json` and `zh.json`. Run `node build.mjs`, then `python3 scripts/copy-deck.py` to refresh the copy decks.
- **Prices:** edit `src/data/prices.json`. The amounts appear on Home, Suits & pricing and in structured data. The FAQ answer and SEO descriptions quote prices in words, so update `faq` and `pages.pricing.description` in all three language files too.
- **Reviews:** `src/data/reviews.json`. Quote reviews word for word, and refresh the rating and count before launch.
- **Journal:** one JSON file per post in `src/data/journal/` (title, excerpt and HTML per language). Cover photos are mapped in `COVERS` in `build.mjs`.
- **Photos:** put source files in `_source/`, add them to `MAP` in `scripts/prepare-images.py`, and run it. That writes WebP files plus 900px variants and records their sizes.

## Deploy the proposal to Vercel

The live proposal is at **https://phans-custom-tailor-demo.vercel.app**. It's Vercel project `phans-custom-tailor-demo` on team `thewebxiteai-6218s-projects`.

```
node build.mjs                 # keeps dist/.vercel, so redeploys go to the same project
cd dist && npx vercel deploy --prod --yes --scope thewebxiteai-6218s-projects
```

The build writes three Vercel files into `dist/`:
- `dist/vercel.json` holds the 301 redirects from the old Haravan URLs (with and without a trailing slash).
- The same `vercel.json` adds a `noindex` header while `indexable` is false. Every page also carries a `noindex` meta tag.
- `dist/.vercelignore` keeps `_hosting/` and any `.env*` files out of the upload.

## Launch on our hosting

1. Set `"indexable": true` in `src/config.json`, or run `INDEXABLE=true node build.mjs`. This removes `noindex` and writes `robots.txt` and `sitemap.xml` (with hreflang).
2. Check `siteUrl` in `src/config.json` is the final domain. It's used for canonical, hreflang, Open Graph and the form's `_next` URL.
3. Upload the contents of `dist/` to the web root.
4. Redirects and 404:
   - **Apache:** copy `dist/_hosting/.htaccess` to the web root.
   - **nginx:** include `dist/_hosting/nginx-redirects.conf` in the server block.
   - On both, `404.html` is the not-found page.
5. Point the domain. The old URLs (`/pages/...`, `/blogs/news/...`, `/products/...`, `/collections/...`) redirect to the new pages.

## Enquiry form (FormSubmit)

The Contact form posts to `https://formsubmit.co/info@phantailor.com`. With JavaScript it posts to the AJAX endpoint and then goes to `/contact/thank-you/`; without JavaScript, the normal form post still works.

- **Activation:** the first real submission sends an activation email to info@phantailor.com, and the client must click it before enquiries are delivered. After activating, FormSubmit can give a random alias; put it in `config.forms.formsubmitEmail` to hide the address from the page source.
- **Captcha:** FormSubmit's captcha is on by default, but only for the non-JavaScript post.
- **Spam:** a honeypot field (`_honey`) is included.
- **Test inbox:** during the proposal, test with your own address in `config.forms.formsubmitEmail` so the client doesn't get test enquiries.

## Connect WooCommerce (the shop)

The shop pages are built from WooCommerce's public **Store API** (`/wp-json/wc/store/v1/products`). It's read-only, so no API keys reach the browser.

1. Install WordPress and WooCommerce on a subdomain, for example `shop.tailormadesuit.net`. Use pretty permalinks.
2. Create two product categories with these slugs: `nobility-fabrics` and `ready-made`. Add a global attribute named `Colour`, whose term slugs are used as filters, plus `Composition`, `Size`, `Sold by` and `Brand` as needed. Set prices in VND with 0 decimals.
3. In `src/config.json`, set `shop.storeApiBase` to `https://shop.tailormadesuit.net`. The build then fetches products from the API and generates a static page for each (`/shop/<slug>/`). Rebuild and redeploy after product changes, or trigger a Vercel deploy hook from WooCommerce on product save.
4. Set `shop.checkoutEnabled` to `true`. "Add to bag" then goes to `https://shop.../cart/?add-to-cart=<id>`, and WooCommerce handles the cart, checkout, payment and emails. While it's `false`, "Add to bag" opens WhatsApp with the product name.
5. **Theme:** use a minimal theme on the WordPress subdomain, such as Storefront or Kadence, and style its cart and checkout to match: ink `#141414`, background `#f7f6f3`, accent `#1e2a3a`, Prata for headings and Hanken Grotesk for text. Hide its shop and product pages, or redirect them to the static site, so customers only see cart and checkout there.
6. **Payment gateways:** choose with the client. VNPay, MoMo, OnePay and Stripe (cards) all work with VND.
7. **CORS:** not needed for the build-time fetch. If you later add live client-side stock checks, allow the static domain on the WordPress side.
8. **Languages:** the Store API returns one language. For Vietnamese and Chinese product names, either use a multilingual plugin (WPML or Polylang with WooCommerce support) and fetch with `?lang=vi`, or keep the translations in a custom field. The sample products show the shape we use: `pct_i18n.vi` and `pct_i18n.zh`.

## QA

```
cd dist && python3 -m http.server 4321 &
python3 scripts/qa.py           # all checks
python3 scripts/shots.py        # full-page screenshots of 18 key pages at 360-1920px and 844x390 into qa/
python3 scripts/perf.py         # LCP, layout shift and page weight on throttled mobile (slow 4G, 4x CPU)
```
The script checks:
- internal links and anchors
- emoji, leftovers from the old site and banned words
- keyword placement
- horizontal scroll at every breakpoint
- the language switch and hreflang
- shop filters and their URL state
- the enquiry form: validation and submission, with FormSubmit intercepted
- dataLayer events
- the mobile menu and keyboard access
- the site without JavaScript
- reduced motion

## Header, menu and hero

- **Header:** a menu button on the left, the logo centred, and the language switch and booking on the right.
- **Menu:** the button opens a full-screen menu (`menuOverlay()` in `build.mjs`). Each item's preview photo is set in the `MENU` list there. Without JavaScript the menu still opens through the `#pct-menu` link.
- **Home hero:** the campaign photo with the section links in `home.heroLinks` in each language file. Each link has a target page and the photo it shows on hover.

## Motion

`src/js/motion.js` adds all the movement:
- GSAP: line-by-line headline reveals, image reveals and parallax, drawn rules, price count-ups, the mill-name marquee, the word-by-word review quote, magnetic buttons, the cursor follower, the hide-on-scroll header and page transitions.
- three.js: a rippling hero photo and a 3D cloth on the windowpane band. three.js only loads after the page has loaded, never on data-saver connections, and pauses when off screen.

How it behaves when motion is off:
- **Without JavaScript**, or with "reduce motion" set on the device, the site is fully static and complete.
- **If the motion script fails**, a 4-second safety timer reveals any text it was holding back.

To tune it:
- **Effects:** each one is a short, commented block in `motion.js`.
- **Shaders:** the WebGL shaders are the `RIPPLE_*` and `CLOTH_*` strings.
- **Images:** the hero and band images come from the `data-pct-gl-src` attributes set in `build.mjs`.

**Licences:** GSAP is free under the GSAP Standard "no charge" license (gsap.com/standard-license), including SplitText. three.js is MIT.

## Analytics

Every click on booking, WhatsApp, Zalo, call, email, Add to bag, the language switch and the form submission pushes a `dataLayer` event. These are `book_click`, `whatsapp_click`, `zalo_click`, `call_click`, `email_click`, `add_to_bag`, `language_switch`, `form_submit`, `shop_filter` and `video_play`, each with a `where` value where relevant. Add Google Tag Manager or GA4 to the `<head>` in `documentHTML()` in `build.mjs` when the client is ready.
